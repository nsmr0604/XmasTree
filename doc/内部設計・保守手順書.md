# 内部設計・保守手順書

## 1. 対象と前提

この文書は、現行のブラウザーアプリの構成、イベント・データの流れ、設定変更時の注意、手動確認項目をまとめたものです。関数ごとの引数・戻り値は[関数仕様書](./関数仕様書.md)、画面操作と保存データの概要は[スタッフ向け詳細仕様書](./スタッフ向け詳細仕様書.md)を参照してください。

アプリのソースパスはリポジトリルートを基準とします。アプリ側にはビルド工程、外部API、テスト設定はありません。同梱のThree.jsは `assets/three/` にあります。静的ファイルはHTTPサーバーから配信し、WebGL・JavaScript ES Modules・JSON import attributesが使えるブラウザーで実行します。

## 2. 構成と依存関係

役割はMVCに従います。Controllerが入力イベントを、Modelが状態・永続化・配置計算を、ViewがDOM表示と3D描画を担い、`assets/app.js` が組み立てて起動します。3Dオブジェクト生成器は表示部品のためView層の `assets/views/scene/` 配下にあります。

```text
index.html
  └─ assets/app.js
       ├─ config/settings.js ── scene-settings.json / app-settings.json
       ├─ AppView ── DOM
       ├─ SceneView ── Three.js / PrintLayout / views/scene/ のオブジェクト生成器
       ├─ DecorationStore ── localStorage
       ├─ DecorationModel ── SceneView.tree / 飾り生成器 / DecorationStore
       │    └─ decoration-position.js（配置探索）→ decoration-orientation.js（姿勢計算）
       ├─ DecorationController ── DecorationModel / SceneView / AppView
       ├─ SaveCodeController ── DecorationModel / AppView
       └─ SceneController ── SceneView / AppView
```

`settings.js` は `{ ...sceneSettings, ...appSettings }` でトップレベルを浅く統合します。同名トップレベルキーがあれば `app-settings.json` 側が優先されます。各シーンオブジェクト生成器（`views/scene/` 配下）も同じ設定モジュールを直接参照します。`SceneView` は舞台全体の組み立てを `views/scene/landscape.js` に、印刷レイアウトを `views/print-layout.js` に委譲します。

### 起動シーケンス

1. `index.html` がCSSと `assets/app.js` を読み込む。
2. `app.js` が飾りtypeと生成関数を対応付け、AppViewとSceneViewを生成する。
3. StoreとModelを生成し、`DecorationController` と `SaveCodeController` の `start()` でイベント登録とactive状態の復元を試みる。active状態がなければ空状態を保存する。
4. `SceneController` の `start()` でカメラ・昼夜・印刷のイベントを登録し、SceneViewが `requestAnimationFrame` ループを開始する。
5. 各フレームで降雪と時計を更新してシーンを描画する。

設定JSONの読み込み、DOM要素、WebGL初期化、シーン生成などに失敗すると、アプリの起動自体が完了しない場合があります。

## 3. イベントとデータフロー

| 入力 / イベント | 実装上の流れ |
|---|---|
| 飾りボタン | `DecorationController.selectDecoration` → 選択typeを更新 → `AppView.setSelectedDecoration` / `setStatus`。 |
| マウスホイール | canvas上で `DecorationController.cycleDecoration` → 飾りボタンのDOM順序で次/前のボタン → `selectDecorationButton` と同じ画面更新。下ろして次、上げて前。 |
| 葉のクリック | `placeDecoration` → Raycasterで葉との交差 → 葉ローカル位置 → `DecorationModel.add` → `decoration-position.js` による候補探索・追加 → `save` → Store書き込み。 |
| Mキー | `SaveCodeController.handleKeyDown` → 保存番号フォームの表示切替。開く際に現在番号を入力しフォーカスする。入力欄・テキスト欄内のMでは切り替えない。 |
| 番号呼び出し | form submit → `SaveCodeController.loadByCode` → 番号の形式チェック → `model.load` → Store読込・検証 → 現在の飾りを破棄して復元。呼び出しのみではactiveキーを書き換えない。 |
| 初期化（新番号） | `SaveCodeController.reset` → 未使用番号発行 → 全飾り破棄 → 空状態を新番号で保存。旧番号の状態は残る。 |
| Delete | `SaveCodeController.requestReset` → 1回目は確認メッセージを表示して待ち状態にし、2回目の押下で reset → 未使用番号発行 → 全飾り破棄 → 新番号の空状態を保存。旧番号のデータは残る。Deleteは入力欄フォーカス時にも確認つきで処理される。待ち状態はDelete以外のキー押下やcanvasのクリック・ホイール、飾りボタンの選択、初期化ボタンで解除される。 |
| W/S/A/D | `SceneController.handleKeyDown` → `SceneView.moveCamera`。キーリピートによる継続操作も処理する。 |
| L / P | Lは背景・夜間表示を切替、Pは押下中に印刷ボタンと案内を表示。Pのキーアップまたはblurで非表示。 |
| 印刷 | 印刷ボタンはPNG生成・decode後に `window.print`。ブラウザーの `beforeprint` でもPNG生成を行い、`afterprint` で画面カメラを戻す。 |
| resize | 描画サイズとカメラアスペクト比をウィンドウに合わせる。 |

SceneControllerのキー処理には入力欄フォーカスの除外がありません。操作の追加や変更時は、保存番号入力中の挙動も確認してください。

## 4. 飾りの配置と状態

### 配置処理

1. 画面クリック座標を正規化し、カメラからRaycasterを飛ばす。葉以外へのクリックは何もしない。
2. 最初に交差した葉に対するローカル座標を `add` に渡す。
3. 全体・種類別上限を確認し、`nextDecoration` と種類別個数からサイズ・色を決定して飾りを生成する。
4. `decoration-position.js` が葉の円錐上でクリック位置に近い高さ・角度の候補を探索する。候補の位置と法線をツリーローカルに変換する。
5. `decoration-orientation.js` による飾りの姿勢、境界箱の法線方向投影、既存飾りとの間隔を考慮し、使える候補があればツリーに追加する。見つからなければ仮飾りのGeometry・Materialを破棄してエラーにする。
6. 保存用userDataを設定し `nextDecoration` を増やして保存する。

サイズは全体通し番号で配列を循環します。雪の結晶の色は同種個数で専用色配列を循環し、それ以外は全体通し番号で共通色配列を循環します。キャンディケインの生成器は渡された色を使用せず、設定の縞色を使います。

### 重要なデータと座標

| データ | 管理箇所 / 意味 |
|---|---|
| `selectedType` | DecorationControllerが保持する次に置く種類。保存対象ではない。 |
| `decorations` | DecorationModelが保持する配置済みGroupの配列。各Groupはツリーの子。 |
| `nextDecoration` | Modelが保持するサイズ・共通色選択用の通し番号。削除・初期化時は0。 |
| `currentCode` | Modelが保持する現在の保存番号。ロード時も更新されるが、ロードのみではストレージのactiveキーは変わらない。 |
| 葉の `coneRadius` / `coneHeight` | 葉MeshのuserData。円錐上の候補と法線の計算に使う。 |
| 飾りの `clearanceRadius` | 飾りGroupのuserData。既存飾りとの中心距離による衝突回避に使う。 |
| 飾りの `position` / `quaternion` / `scale` | ツリーのローカル座標系の変換。配列化して保存し、復元時に姿勢を正規化する。 |

飾り削除・復元時は `disposeDecoration` が各MeshのGeometryとMaterialを重複なく破棄します。飾り生成器が新しい共有リソースやテクスチャを導入する場合は、その所有権と破棄方法を設計してください。

## 5. 保存、復元、失敗時の挙動

### キーと状態

| Local Storageキー | 内容 |
|---|---|
| `christmas-tree-decoration-state:<番号>` | 番号別のJSON。`saveCode`、`nextDecoration`、`decorations` を保持。 |
| `christmas-tree-active-decoration-state` | 次回起動時に読み込む番号。 |

保存形式と検証条件の詳細は[スタッフ向け詳細仕様書](./スタッフ向け詳細仕様書.md#4-保存仕様)を参照してください。状態全体・飾りごとのキー集合は厳密に検証されるため、フィールドの追加・名前変更やtype変更には移行方針が必要です。発行番号は現在100000〜999999ですが、入力・保存データ検証は6桁の半角数字かどうかを確認します。

### 保存操作ごとの違い

| 操作 | 番号別JSON | activeキー |
|---|---|---|
| 新規起動時の空状態保存 | 新番号を作成 | 新番号に更新 |
| 飾り追加 | 現在番号を上書き | 現在番号に更新 |
| Delete（2回目の押下） | 未使用番号を発行しその空状態を作成。旧番号は残す | 新番号に更新 |
| 新番号で初期化 | 新番号の空状態を作成。旧番号は残す | 新番号に更新 |
| 番号呼び出し | 読み込みのみ | 更新しない |

呼び出した番号が次回起動時の復元対象になるのは、その番号で次に保存が成功したときです。ブラウザー、プロファイル、オリジン（スキーム・ホスト・ポート）が変わると別の保存領域になります。

### 例外と復旧時の注意

- 保存時は番号別データ、次にactiveキーの順で2回書き込みます。片方だけ成功する可能性があり、原子的な更新ではありません。
- 追加・初期化では画面上の飾りを変更した後に保存するため、保存に失敗しても変更前の画面へ自動的に戻りません。画面の状態と保存済みデータが一致しない可能性があります。
- 起動時のactive復元に失敗するとConsoleに記録し、Modelの現在状態の保存を試みます。起動時の保存失敗もConsoleに記録されますが、その処理自体は画面にエラーを表示しません。
- 手動読み込み・配置・初期化・削除の失敗はConsoleと状態パネルに表示されます。印刷ボタン経由の失敗は画面カメラを戻しConsoleに記録します。
- ブラウザー設定、容量、プライベートブラウズ等によって保存が使えない・消去される場合があります。サイトデータの消去は保存データを削除するため、確認時は既存データを消さないようにしてください。

## 6. 設定リファレンス

設定はJSONが正本です。詳細な形状・配列値は各ファイルを確認してください。

### [app-settings.json](../assets/config/app-settings.json)

| トップレベル | 主な内容 / 変更時の注意 |
|---|---|
| `saveCode` | 桁数、発行範囲、発行試行回数。入力制約と検証にも桁数を使用。桁数・範囲変更は既存番号の互換性を確認する。 |
| `decorationPlacement` | 候補の角度刻み・探索数・表面オフセット・姿勢計算の閾値。配置可否と見た目に影響。 |
| `decorations` | 個数上限、共通色・サイズと各飾りの形状・材質・クリアランス。上限を下げると既存データが検証に失敗することがある。 |
| `controls` | 初期飾り、キー、移動・回転幅、高さ探索幅、衝突gap。初期typeはHTMLのボタンと生成器に存在する必要がある。 |

### [scene-settings.json](../assets/config/scene-settings.json)

| トップレベル | 主な内容 |
|---|---|
| `camera` | 通常・印刷カメラの視野角、位置、注視点、ズーム範囲。 |
| `print` | 用紙サイズ、出力画像サイズ、ヘッダー・番号の位置とフォントサイズ。 |
| `background` | 昼・夜の背景色。 |
| `tree` | 幹、葉、頂上の星の形状・色。葉の半径・高さは配置探索にも使う。 |
| `floor` / `floorText` | 床半径、床面高さ、レンガと床文字の設定。 |
| `house` / `floorGiftBoxes` / `santa` / `clockTower` | 舞台オブジェクトの位置・形状・色・配置条件。 |
| `snowfall` | 雪レイヤー、個数、落下・風・テクスチャの設定。 |
| `lighting` | 環境光・平行光源の色、強さ、位置。 |

床ギフトの後方配置は乱数探索で、指定の試行回数で配置できなければ例外になります。床や葉、家の寸法を変更した場合は複数回起動して配置条件を確認してください。

## 7. 保守・拡張手順

新規モジュールのファイル名は、default exportするクラス名・生成関数名のkebab-caseにします（[関数仕様書](./関数仕様書.md)のファイル名規則を参照）。

### 飾りを追加する場合

1. `assets/views/scene/decorations/` に生成器を追加し、サイズ・色から `THREE.Group` を返す。配置探索用の `userData.clearanceRadius` を設定する。生成関数名は `create` + typeキーの頭大文字（例: type `candyCane` なら `createCandyCane`）とし、ファイル名はtypeキーのkebab-caseにする。
2. 必要な形状・材質設定を `app-settings.json` に追加する。
3. `assets/app.js` で生成器をimportし、`decorationFactories` にtypeを登録する。Storeはこのキー一覧から許可typeを得る。
4. `index.html` に同じtypeの `data-decoration` ボタンを追加する。初期typeを変える場合は `controls.initialDecoration` も合わせる。
5. 既存データのtypeやJSON形式を不用意に変更しない。変更が必要なら既存保存データの移行方法を決める。
6. 配置、衝突、削除、保存・復元、印刷を確認し、利用者・スタッフ向け文書と関数仕様書を更新する。

### 設定・DOMを変更する場合

- 制限値や操作キーを変えたら、利用者向けの操作説明、詳細仕様、確認項目と一致させる。
- DOMのIDや構造を変更したら、`AppView` と各Controllerの参照、`hidden`・`aria-pressed`、印刷用CSSを合わせて確認する。
- 印刷サイズを変えたら、`print` 設定とCSSの `@page` 指定の整合性を確認し、印刷プレビューで画像・日付・番号を確認する。
- 設定や形状の変更後は、保存済み状態の復元、境界・姿勢、カメラ距離、画面リサイズも確認する。

## 8. 手動確認チェックリスト

この項目は実装変更時に行う推奨確認であり、実行済みのテスト結果ではありません。既存の保存データを変更しないよう、検証専用のブラウザープロファイルや別オリジンを使ってください。各確認は設定が既定値の場合の期待結果です。

1. **起動**：ルートで `python -m http.server 8000` を実行し、`http://localhost:8000/` を開く。ツリー・床・雪・時計と操作UIが表示され、Consoleに起動エラーがないこと。
2. **選択と配置**：8種類それぞれを選び葉をクリックし、選択状態と対応する飾りの配置を確認する。マウスホイールで選択がボタン順序の前後へ変わり、先頭と末尾で折り返すことも確認する。葉以外をクリックしても増えないことを確認する。
3. **上限**：空状態から1種類を20個置き、21個目が種類別上限で拒否されることを確認する。別の空状態で複数種類を合計50個置き、51個目が全体上限で拒否されることを確認する。置ける場所がない場合は別の葉や角度を試す。
4. **保存と復元**：飾りを置いて番号を控え、ページを再読み込みして同じ配置が復元されることを確認する。新番号で初期化し、旧番号を呼び出して旧配置が戻ることを確認する。
5. **active番号**：新番号で保存後に旧番号を呼び出し、変更せず再読み込みすると新番号が復元されることを確認する。旧番号を再び呼び出して飾りを追加し、再読み込みすると旧番号が復元されることを確認する。
6. **削除と入力**：Deleteを1回押すと確認メッセージだけが表示されて初期化されないこと、もう一度押すと未使用の保存番号が発行され飾りが空になり、その番号で保存されることを確認する。旧番号のデータが残り呼び出せることも確認する。Delete以外のキーを押すと確認待ちが解除されることも確認する。番号欄の非数字除去・桁数制限、不正番号のエラーを確認する。入力欄でDeleteを押しても確認つきで初期化される現行挙動に注意する。
7. **カメラ・昼夜**：W/Sの距離制限、A/Dの回転、Lの昼夜切替を確認する。画面をリサイズして描画が追従することも確認する。
8. **印刷**：Pを押しながら印刷ボタンを押し、印刷プレビューでA4縦の画像・日付・所属・保存番号を確認する。キャンセル後に通常画面へ戻ることを確認し、ブラウザーの印刷操作からも確認する。
9. **保存失敗**：検証専用環境でストレージが使えない場合のConsoleと画面の通知を確認する。失敗後は画面と保存済み状態が一致しない場合があるため、保存データを保護してから行う。

終了時はHTTPサーバーを起動したターミナルで `Ctrl+C` を押します。
